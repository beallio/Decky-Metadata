# SteamGridDB artwork compatibility implementation — 2026-08-27

## Objective

Preserve the native shortcut identity for matched non-Steam shortcuts outside
their own Library Game Info route. This lets Steam's artwork resolver request
the shortcut icon on Library Home while preserving Decky Metadata's rich matched
Game Info behavior.

## Route and precedence decision

`BIsModOrShortcut` keeps Steam's native true value unless the call is for the
same matched shortcut on a recognized Library app/detail route. The order is:
native/non-shortcut pass-through, in-call launch truth, unmatched pass-through,
outside-detail pass-through, current-detail route shield, current-detail truth
window, then current-detail false spoof. Outside-detail calls do not consult a
route shield or decrement the bypass counter.

The live hard-reload check found `Router` absent in the SharedJSContext while
`window.location` still held the Game Info route. The fallback was necessary:
without it the strict classifier correctly saw no route, which also prevented
the matched Game Info quick-links row. The focused test reproduces this Steam
context shape.

## Device evidence

### Baseline

The unmodified bundle was deployed through CDP port 18085. On Library Home for
shortcut `2155012430` and matched Steam app `55150`, the requested object was
the shortcut, the matched lookup aliased to that same object, `BIsShortcut` was
true, `BIsModOrShortcut` was false, and both icon fields were absent. The
bounded incorrect app-ID icon call stayed unresolved, matching the reported
identity failure. A Library Home screenshot and scalar/hash-only payloads are
in the task temp directory.

The artwork probe's source confirms the actual resolver takes the overview
object; the permanent probe uses that call and bounded retries. The six
referenced custom-art files were present before the change. Their content hashes
were captured without paths.

### Post-change

Review round 01 explicitly authorized the current device and left it on Library
Home. A new redacted pre-deploy file audit captured six shortcut custom-art
files. The corrected commit deployed through CDP port 18085. The final Library
Home smoke reported the requested shortcut object, unchanged matched-object
alias, `BIsShortcut=true`, `BIsModOrShortcut=true`, non-null icon resolution,
and six unchanged SHA-256 values before and after. Steam candidate URL counts
were two each for vertical, landscape, hero, and logo; they are diagnostics,
not the preservation oracle. No artwork was written or reapplied.

The first four short icon polls (450 ms total) correctly retained native
shortcut identity but did not wait long enough for Steam's asynchronous icon
cache fill. A bounded diagnostic then resolved the same icon on its next poll.
The permanent probe now permits at most 20 polls over five seconds. It passed
on the immediate rerun and records only the resolved boolean and a short value
hash, never the URL.

The Library Home screenshot shows the affected Space Marine tile with its
custom artwork rather than a blank icon. A Game Info screenshot shows the
matched Game Info route still renders the custom capsule and rich content. The
Library Home portrait, background presentation, and Game Info capsule were
visually inspected; the hashed candidate evidence confirms the existing wide,
hero, and logo sources remain present without exposing their values.

The authorized committed launch smoke passed for `2155012430`: it used the
64-bit shortcut game ID `9255707909357043712`, sent the committed termination
request, and a five-second follow-up showed zero running games. The targeted
rerender smoke passed with zero same-app cache writes across three subsection
round-trips. The quick-links smoke and `run_all.sh --no-launch` both report the
pre-existing stale delisted-fixture problem (`delisted game lost rich metadata`);
the no-launch suite also reports empty delisted-source Community rows. Its
rerender and no-fallback Community controls passed, but the suite is not
recorded as passing.

### Review round 02 device recheck

The corrected bundle was redeployed through CDP port 18085. The first bounded
Library Home artwork smoke kept the requested shortcut object, alias, native
shortcut identity, and all eight custom-art candidate counts, but Steam had not
hydrated its icon cache after 20 attempts / 5.03 seconds. Read-only diagnostics
showed no new active plugin fault; the audit contains prior reload/shutdown and
network noise only. A subsequent bounded smoke on the unchanged Library Home
route resolved the icon on its first attempt (27 ms) and confirmed six unchanged
artwork-file hashes. No artwork was written or reapplied.

The matched/never-on-Steam quick-links check passed, and the matched rerender
check again reported zero cache writes across three subsection round-trips. The
full no-launch suite completed: rerender and empty-fallback Community controls
passed, while the existing delisted metadata and delisted Community-source
fixtures failed. The authorized launch validation also launched and terminated
the matched shortcut with its 64-bit game ID; its dispatcher exit remains
nonzero only because the known delisted quick-links fixture failed. These two
delisted failures are recorded separately and are not called passes.
