# Controller type filtering

## Date

2026-08-26

## Objective

Implement the `controller-type-filtering` plan: keep Steam's requested source
filter for normal and unknown controller types, force only the matched-source
query to unfiltered for the verified Legion Go S type `102`, and surface the
connected controller types in the Quick Access Menu Versions section.

## Controller policy

- The controller is resolved solely by the `controllerIndex` from
  `QueryControllerConfigsForApp` arguments.
- Type `4` (Steam Deck), unknown, unavailable, and external/future types keep
  Steam's requested source filter.
- Type `102` (Legion Go S) is the sole entry in the explicit affected allowlist
  and changes only its supplemental matched-source query to `false`.
- Primary shortcut queries and Steam's visible
  `m_bFilterOtherControllerTypes` setting remain untouched. Steam's existing
  getter equivalence filter therefore continues to control visible results.
- The Versions panel samples `ControllerStore.GetControllers()` once at mount,
  prefers `ControllerStore` over `controllerStore`, and formats sorted unique
  types as diagnostics. It does not enumerate MobX stores or poll hot-plug
  changes.

### Review round 01 corrections

- `9c4c4a0 fix(controller): harden supplemental layout filtering` invalidates
  both the effective supplemental key and its Search classification whenever
  Steam queries that known source app natively. The affected regression covers
  shortcut (`true`) -> matched source (`false`) -> native source (`true`) ->
  shortcut (`false`) so Steam cannot leave the shared cache filtered while the
  wrapper believes its unfiltered source is still present.
- Controller-store discovery, `GetControllers`, and both controller-record
  fields are now conservative boundaries. Throwing accessors/proxies and
  string, fractional, or negative types render no controller type rather than
  propagating through the QAM mount effect.
- The bounded layout probe now serializes its controller type only after it is
  a non-negative integer and serializes the visible filter only after it is a
  boolean. `test_deck_fixture_selection.py` checks those values are fields of
  the root serialized payload, not merely identifiers elsewhere in the probe.
- `a4a606d docs(readme): clarify Legion controller layout support` states the
  intended user-visible contract: the verified Legion Go S type `102` retains
  compatible matched-game layouts while Steam's visible controller filter
  stays enabled; no such workaround is claimed for other types.
